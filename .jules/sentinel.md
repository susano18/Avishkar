## 2026-04-25 - [Privilege Escalation via Mass Assignment]
**Vulnerability:** The registration endpoint (`/auth/register`) accepted a `role` field in the request body, allowing users to register themselves with any role, including `admin` or `educator`.
**Learning:** Using a single model for both input validation and database representation without filtering sensitive fields can lead to mass assignment vulnerabilities. Pydantic models used for API requests should only include fields that users are explicitly allowed to provide.
**Prevention:** 1) Use dedicated request schemas that exclude sensitive fields like `role`, `is_active`, or `permissions`. 2) Explicitly set sensitive defaults in the application logic rather than relying on request data. 3) Always verify user-provided data against the principle of least privilege.

## 2026-06-10 - [Resource Exhaustion and Information Leakage]
**Vulnerability:** The application lacked file size validation for uploads, creating a Denial-of-Service (DoS) risk. Additionally, internal error messages (including file paths and API errors) were leaked to the client in exception responses.
**Learning:** FastAPI's `UploadFile.size` attribute is not available in all versions (including the current environment). Robust size validation must be performed by manually seeking to the end of the underlying file object. Generic error messages are essential in security-critical paths to prevent revealing server internals to potential attackers.
**Prevention:** 1) Implement manual file size checks using `file.file.seek(0, 2)` and `file.file.tell()` before processing uploads. 2) Log full exception details internally using structured logging while raising `HTTPException` with generic, user-safe `detail` strings. 3) Enforce essential security headers (CSP, HSTS, X-Frame-Options) via middleware as a baseline layer of defense.
